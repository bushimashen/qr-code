## 风格不只是好看

二维码本质是一张黑白模块网格，你对它做的任何装饰，都是在和「能不能扫出来」做交换。
所以这里把**数据图案**和**盖在上面的画法**严格分开：

- 模块矩阵完全来自 `qrcode-generator`，样式不会改动它一个点。
- **三个定位角永远画成完整的实心环**（方框/圆角/圆点），无论主体用哪种风格——扫描器最先抓的就是它们。
- 装饰边框与横幅一律画在**静区之外**，绝不压在数据上。
- 中心 Logo 会挖掉底下的码点，这正是容错等级的用途——所以放了 Logo 就建议用 **Q 或 H**。

## 实现要点

**绘制是一串「模块坐标系下的图元指令」**，不是直接调 canvas。每种风格只产出
`path` / `circle` / `poly` / `ring` / `rect` / `text` 这些 op，然后由两个后端分别消费——
一个画到 `<canvas>`，一个序列化成 `<svg>`。这保证了 PNG 和 SVG 长得**一模一样**，
也保证了「加一种新风格」只需要在一个 switch 里加一个 `case`。

**随机类风格用固定种子。** `星屑抖动` / `方粒拼贴` / `随机拼块` 是随机的，但种子是
`hash(styleId + seed)`，所以同样的内容和参数永远重绘出同一张码——否则你每动一下滑块，
设计就变一次。「换一组随机细节」按钮才是真的重新掷骰子。

**中文内容必须换 UTF-8 编码器。** `qrcode-generator` 默认按单字节处理，不写
`qrcode.stringToBytes = qrcode.stringToBytesFuncs['UTF-8']` 的话，中文会编码成乱码。
这一行之差，就是「能扫」和「好看但没用」的区别。

## 怎么用

把整个目录下载下来打开 `index.html` —— 指向 `vendor/` 的相对路径要保持完整。

```bash
python -m http.server 8000   # 或者用任意静态服务
```

## 印刷前请务必实扫

预览只是「渲染效果」，不等于「已验证可扫」。送去印刷前，请用**两台不同的手机**各扫一次——
尤其是你加了 Logo、用了低对比度的渐变、或者在小尺寸下选了 `十字网格` / `编码条纹` 这类高密度风格时。
另外：内容越长矩阵越密，越密的矩阵对装饰的容忍度越低。
